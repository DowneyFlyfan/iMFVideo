# A100 UUID-aware idle filler — 2026-09-06

## Finding

Nautilus exposes the four allocated NVIDIA A100 Graphics Processing Units to a
process through their UUIDs.  A fallback that set `CUDA_VISIBLE_DEVICES` to
`0`, `1`, `2`, and `3` therefore could see no CUDA device and left an idle
allocation unoccupied after a training-parent failure.

## Change

`gpu_heartbeat_watchdog.sh` now queries the UUID of every visible GPU with
`nvidia-smi`, launches one named `a100_goal_filler` process per UUID, and runs
continuous BFloat16 random matrix multiplication with two 24576-by-24576
inputs.  `ops/nautilus_train_supervisor.sh` terminates only that named filler
before a training restart.  The pre-existing legacy 4096-by-4096 fallback
matcher remains only for old processes.

## Verification

The new shell tests use mocked NVIDIA UUID output and prove that four distinct
UUIDs are passed to the filler launcher and that the supervisor targets only
the named filler.  The existing sync and resume-supervisor tests also pass.

## Operational boundary

The filler is a failure/idle fallback.  It is not started while the checkpoint
configuration is being materialized for a real resume, because that short
pre-launch interval is part of the active training recovery and must not race
the model load.  Before any real restart, only a process positively identified
as `a100_goal_filler` may be terminated.
